# 내보내는 파일의 개인정보

화면 안에서는 괜찮던 정보도 **파일이 되면 기기 밖으로 퍼진다**(카톡·메일·PC 폴더). 한번 나간 파일은 되돌릴 수 없으니,
만들 때부터 이 표를 하나씩 확인한다. 끝나면 `privacy-guard` 로 검토한다.

## 1. 만들기 전에 정한다 (계획서·DATA.md 에 적기)
| 질문 | 예 |
|------|-----|
| 누가 받나 | 회원 본인 / 센터 직원 / 회사(분석·교육) / 외부 |
| 무엇이 꼭 필요한가 | 측정값·좌표만? 사진도? 이름이 정말 필요한가 |
| 어떤 동의가 근거인가 | 촬영·보관 동의, 공유 동의, 사진 활용 동의 — 동의 날짜 칸 이름 |
| 동의를 철회하면 | 이미 만든 파일·기기 보관본은 어떻게 하나 (약관·방침 문구와 같아야 함) |

받는 사람이 회원 본인이 아니면 **이름·연락처·생년·회원번호는 기본으로 넣지 않는다.**

## 2. 체크리스트 (모든 출구를 따라간다)
- [ ] **글자 칸**: 이름 대신 임의 코드(회원 id 를 해시한 짧은 코드, 예: `회원-AB12`). id 가 없으면 이름으로 코드를 만들지 않는다(이름을 추측할 수 있음).
- [ ] **파일 이름**: 이름 대신 코드·날짜. `기록_홍길동_20261021.xlsx` ✗ → `기록_회원-AB12_20261021.xlsx`.
- [ ] **그림 속 글자**: 결과 그림 머리글·워터마크·썸네일에 이름이 **그려져** 있지 않은가(`fillText` 를 쓰는 함수를 찾아본다). 예전에 저장된 그림도 포함 — 이미 그려진 것은 내보낼 때 그 부분을 덮는다.
- [ ] **사진**: 동의한 회원만. 동의가 없으면 사진 칸에 "동의 없음" 글만. 얼굴을 가리는 규칙이 있으면 얼굴을 **못 찾았을 때는 사진을 빼는** 쪽으로(가리지 못한 채 내보내지 않음).
- [ ] **원본 사진**: 배경에 다른 사람이 찍혀 있을 수 있다 → 배경을 지운 사진을 쓰거나, 범위를 정해 사용자 확인.
- [ ] **기계용 칸(JSON 등)**: `member`·`name`·`phone` 같은 칸을 넣지 않는다. 한 번 더 걸러 내는 함수를 둔다.
- [ ] **회원 찾기**: 이름이 아니라 **id 로만** 동의를 찾는다(이름만 같은 다른 회원의 동의가 붙지 않게). 삭제된 회원·기록은 동의 없음.
- [ ] **로그**: 내보내는 중 오류를 `console` 에 찍을 때 회원 정보를 넣지 않는다(오류 객체만).
- [ ] **약관·방침**: 위에서 정한 내용(누가·무엇·얼굴·철회)이 이용약관·개인정보처리방침 문구와 같은가. 다르면 문구를 고칠지 동작을 고칠지 사용자에게 묻는다.
- [ ] **철회·삭제**: 동의 철회·회원 삭제 때 기기 보관본(내보내기용으로 쌓아 둔 사진 등)도 지워지는가. 이미 내려받은 파일은 사용자가 직접 지워야 한다는 안내가 있는가.

## 3. 확인 방법
- 가짜 회원(홍길동, 010-0000-0000)으로 `browser-check` 시나리오를 만들어 실제로 내려받는다.
- 내려받은 파일을 **안까지** 연다: 엑셀은 python `zipfile` 로 `xl/sharedStrings.xml`·시트를 읽어 가짜 이름이 한 번도 안 나오는지, 사진(`xl/media/`) 개수가 동의 규칙과 맞는지 본다.
- 동의 있음·없음·철회된 회원을 각각 한 명씩 넣어 차이를 확인한다.

## 4. 하지 마라
- "관리자만 보니까 괜찮다" — 관리자 PC 의 파일도 퍼진다. 같은 규칙.
- 내보내기 직전에만 이름을 지우기 — 그림·썸네일·파일 이름처럼 다른 출구가 남는다. 출구마다 확인.
- 테스트에 실제 회원 자료 쓰기 — 가짜만.
