# 웹 푸시 알림

> MEDICALLINK(호출·회진·메신저 알림)와 바디샷(하루 두 번 알림)에서 쓴 구조다(2026-10 기준). 서버 함수·비밀키가 걸려 `plan-gate` 대상. 서버 기본은 `supabase-safe`, 손님 기기 등록은 `guest-link`.

## 1. 전체 구조
```
[폰] 알림 허용 → PushManager.subscribe(VAPID 공개키) → 구독 주소를 서버 표에 저장
[DB 트리거 / pg_cron 예약] → pg_net 으로 서버 함수 send-push 호출, 보내는 것은 {kind, id} 뿐
[send-push] 관리자 권한으로 그 행을 다시 읽어 문구를 만들고 web-push 로 발송
[sw.js] push 이벤트 → showNotification, 누르면 그 화면 열기
```
- **VAPID 비밀키는 서버 함수 Secrets 에만.** 공개키만 `js/config.js`.
- 트리거·요청에 **내용(이름·증상)을 싣지 않는다** → DB 로그·요청 기록에 개인정보가 안 남는다. 잠금 화면 문구도 최소로("호출됐어요", "새 메시지 / 보낸 사람 님").
- 직원 화면이 직접 보내면 앱을 닫았을 때 안 간다 → 반드시 서버에서.
- `sw.js` 는 알림에 담긴 주소가 **앱 안 상대 경로**(예: `^[\w-]+\.html(#[\w-]*)?$`)일 때만 열고, 아니면 `./` 를 연다 — 검사 없이 열면 피싱 통로가 된다.
- Database Webhooks(대시보드 설정)보다 트리거 + `pg_net` 이 낫다 — 설정이 저장소(SQL)에 남아 되돌리기·검토가 된다.

## 2. DB ↔ 서버 함수 확인
- 서버 함수는 `verify_jwt` 를 끄고, DB 가 보낸 비밀 헤더로 확인한다: 비밀값은 Supabase **Vault** 에 DB 안에서 무작위로 만들어 두고(`push_secret`), 함수가 확인 SQL 함수로 대조.
- 트리거 함수는 `security definer` (일반 권한으로는 발송 함수를 못 부르므로).
- **발송 도우미 함수**(pg_net 으로 send-push 를 부르고 Vault 비밀값을 읽는 것)와 비밀값 확인 함수는 `revoke all … from public, anon, authenticated` — 안 하면 손님이 RPC 로 직접 불러 발송을 일으킬 수 있다. 비밀값 확인 함수만 `grant … to service_role`.
- **알림 표**(구독·발송 기록·다시 보내기)는 RLS 켜고 정책 0 + `revoke all … from anon, authenticated` — 서버 함수만 접근. 안 하면 남이 기기 알림 주소를 읽고 지울 수 있다. 등록·해제는 열쇠(손님)나 로그인(직원)을 받는 `security definer` 함수로만 (`guest-link` 4번).
- **발송이 실패해도 조용히 넘어간다** — 알림 때문에 호출·접수·저장이 막히면 안 된다.

## 3. 보내기 규칙
- 같은 알림은 **한 번만**: `push_log(kind, id, endpoint)` 로 기록.
- 발송 결과 404·410 = 없어진 구독 → 그 주소 줄을 지운다.
- 같은 기기에는 한 번만 보낸다(같은 주소 줄이 여럿이어도).
- 메신저처럼 잦은 알림은 한 사람·한 방 1분에 1번처럼 묶는다.
- 서버 함수 호출 수(무료 한도)를 계산해 둔다. 매분 예약은 하루 약 1,440번.
- `web-push`(npm)는 Node 용 — Supabase(Deno)에서 되는지 **배포 후 시험 알림**으로 확인.

## 4. 확인될 때까지 다시 보내기 (놓치면 안 되는 알림만)
웹 알림은 한 번 울리고 끝난다. "끌 때까지 울리기" 는 웹으로 안 된다 → 다시 보내기로 흉내.
- 처음 보낼 때 `push_repeat` 에 한 줄, pg_cron 이 매분(다시 보낼 줄이 있을 때만) 불러 **1~2분 간격 최대 3번**. 일이 끝나거나(호출 완료 등) 10분이 지나면 멈춘다.
- **확인**: 알림마다 무작위 확인표(`ack`)를 넣고, `sw.js` 가 `notificationclick`(누름)·`notificationclose`(밀어서 지움) 때 확인 함수를 부른다. 화면을 열 때도 확인.
  - 확인표는 그 알림 다시 보내기만 멈출 수 있고 몇 분만 살아서 원문 저장해도 된다.
  - `sw.js` 는 앱 코드를 못 불러오므로 Supabase 공개 주소·키를 복사해 REST 로 부른다 → 테스트로 원본과 같은지 검사.
  - 기기에 따라 밀어서 지울 때 신호가 안 올 수 있다(그러면 최대 3번).
- 판정 규칙(언제 다시·언제 멈춤)은 `js/logic/` 에 순수 함수로 두고 테스트, 서버 함수에 복사.

## 5. 폰 한 대 · 여러 곳
- 구독 표는 "(주소, 대상)" 마다 한 줄 — 같은 폰으로 다른 곳(입원·외래, 여러 회원)의 알림을 같이 받게. 등록할 때 다른 줄을 지우지 않는다.
- [알림 끄기] 는 그 화면 줄만 지우고, 남은 줄이 없을 때만 브라우저 구독을 지운다.
- 꺼짐 여부는 화면마다 기기 저장소에 기억해 표시·자동 다시 등록에 쓴다.
- 공용 기기(직원 PC)는 그 기기에서 본인이 [알림 받기] 를 누른 경우만. 로그아웃하면 서버 등록 삭제.

## 6. 폰 주의 (실제 확인)
- **삼성 인터넷**은 [허용]을 눌러도 허용 상태를 기억 못 해 알림이 안 오는 일이 있다(크롬은 정상). ① "알림 켜짐" 표시는 저장한 값이 아니라 `Notification.permission === "granted"` + 실제 구독으로 ② 안 되면 "크롬에서 열어 주세요" ③ 폰 점검표에 삼성 인터넷·크롬 둘 다 ④ 서버는 "보냄" 인데 안 오면 폰 안에서 바로 띄우는 **시험 알림 버튼**으로 폰 쪽 문제인지 먼저 가른다.
- **아이폰**은 홈 화면에 추가한 앱만 알림을 받는다 → 추가 방법 안내.
- Play 앱(TWA)은 알림 권한을 앱에 위임하는 설정이 필요하다 (`pwa-release`).

## 7. 점검
- [ ] 앱을 완전히 닫은 상태에서 잠금 화면에 온다 (크롬·삼성 인터넷·아이폰 홈 화면 앱)
- [ ] 같은 알림이 두 번 오지 않는다
- [ ] 알림 서버를 일부러 끊어도 업무 저장은 된다
- [ ] 잠금 화면 문구·서버 로그에 이름·연락처가 없다
- [ ] 알림을 끄면 다른 곳 알림은 그대로
- [ ] anon 으로 알림 표를 직접 읽으면 0건, 발송 도우미 함수를 RPC 로 부르면 권한 없음
