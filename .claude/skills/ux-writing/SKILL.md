# 화면 문구 쓰기

문구는 앱의 목소리다. 화면마다 말투가 다르면 앱이 어수선해 보이고, 오류 문구가 막연하면 사용자가 멈춘다.
`docs/UI_GUIDE.md` 7번(표준 단어)이 우선이고, 이 스킬은 그 밖의 문장을 쓰는 방법이다.

## 1. 말투는 하나
- 앱이 이미 쓰는 말투를 먼저 확인한다: 알림 문구를 grep 해서 `~어요`(해요체)와 `~습니다`(합쇼체) 중 많은 쪽.
  새 앱은 UI_GUIDE 7번 예시를 따른다. 정한 말투는 `docs/UI_GUIDE.md` 7번에 한 줄로 적어 둔다.
- 한 화면·한 기능 안에서 섞지 않는다. 예전 문구를 한꺼번에 바꾸는 일은 요청이 있을 때만(BACKLOG).
- 느낌표·이모지·"성공적으로" 같은 과장 없이.

## 2. 종류별 모양
| 종류 | 모양 | 예 |
|------|------|-----|
| 성공 | 한 일을 과거형으로 | "저장했어요." |
| 오류 | **무엇이 안 됐는지 + 할 일** | "사진을 저장하지 못했어요. 저장 공간을 확인한 뒤 다시 시도해 주세요." |
| 막힘(조건 부족) | **왜 + 어디서 풀지** | "저장하지 못했어요. 회원 정보에서 '사진 촬영·보관 동의'를 기록한 뒤 다시 저장해 주세요." |
| 빈 화면 | 지금 상태 + 첫 행동 하나 | "아직 회원이 없어요. [회원 추가]로 시작하세요." |
| 확인 창(되돌릴 수 없음) | 무엇이 사라지는지 + 표준 버튼 | "이 기록을 삭제할까요? 되돌릴 수 없어요." [취소] [삭제] |
| 진행 중 | 지금 하는 일 + 개수 | "사진 정리 중… 3/10" |
| 경고(확인 필요) | 무엇을 봐 달라는지 구체적으로 | "턱 앞 점을 확인해 주세요 (턱끝 앞면)" |

## 3. 단어
- 버튼·메뉴는 UI_GUIDE 7번 표준 단어만(저장/취소/닫기/삭제/다음/완료/공유/PDF 저장/촬영/측정). 같은 뜻은 모든 화면에서 같은 단어.
- 전문용어·영어·코드 이름을 화면에 쓰지 않는다: "IndexedDB" → "이 기기", "sync 실패" → "계정 서버에 저장하지 못했어요", "null" → "–" 또는 "없음".
- 숫자 단위는 숫자 뒤에(`2.1°`, `63점`), 날짜 `2026.10.21`.
- 사람을 탓하지 않는다: "잘못 입력하셨습니다" ✗ → "전화번호는 숫자 11자리로 입력해 주세요" ○.

## 4. 길이
- 알림은 한두 문장. 설명이 길어지면 화면 안 도움말이나 자주 묻는 질문으로 옮긴다.
- 메뉴·버튼 아래 설명 문구를 덧붙이지 않는다(공통 규칙).

## 5. 개인정보
- 문구에 회원 이름을 넣을 때는 화면 안 표시만. 오류 메시지·로그·공유 메시지 미리 채움에는 이름을 넣지 않는다(공유 문구는 사용자가 직접 고치게).

## 6. 마무리 확인
- [ ] 새 문구가 앱의 말투와 같다
- [ ] 오류 문구마다 "할 일" 이 있다
- [ ] 표준 단어 밖의 버튼 이름이 없다
- [ ] 영어·코드 이름·느낌표가 없다
- [ ] 390px 폭에서 한 줄·두 줄로 읽힌다(잘리면 줄인다)
