# 브라우저 점검 (시나리오 한 장)

자동 테스트(`npm test`)는 **계산**만 본다. 버튼 → 저장소 → 파일 같은 **흐름**은 이 방법으로 확인한다.
화면 모양만 보려면 `screenshot.py`, 로그인 뒤 배포된 화면은 `app-capture` 를 쓴다.

## 쓰는 순서
1. 시나리오를 `tests/browser/{기능}.json` 에 쓴다 (모양은 `scripts/browser_check.py` 맨 위 설명).
2. 실행: `python scripts/browser_check.py tests/browser/{기능}.json`
3. 결과 줄(통과/실패)과 `.shots/` 의 사진·내려받은 파일을 직접 확인한다. 내려받은 파일은 **안까지** 열어 본다(엑셀은 python `zipfile` 로 시트·칸 글자 확인).
4. 사용자에게는 "몇 단계 중 몇 단계 통과 + 확인한 내용"만 짧게. 이 환경에서 못 해 본 것(실제 카메라 촬영·결제·로그인)은 폰 점검표(`docs/TESTING.md`)로 넘긴다고 말한다.

## 늘 걸리는 함정 (스크립트가 처리하는 것 / 시나리오에 적어야 하는 것)
| 함정 | 처리 |
|------|------|
| 서비스워커가 예전 파일을 보여 줌 | 스크립트가 항상 막음 |
| 로그인·안내 화면이 버튼을 덮어 클릭이 안 됨 | `"hide": ["#로그인화면"]` · 클릭은 화면 안에서 `element.click()` 으로 누름 |
| 앱이 저장소를 첫 실행 때 만듦 | 스크립트가 **먼저 한 번 연 뒤** 자료를 넣고 다시 연다. 없는 저장소 이름이면 실패로 알림 |
| 관리자·설정 같은 켜짐 상태 | `"localStorage": {"키": "값"}` |
| 클라우드·병원 PC 에서 CDN(jsDelivr 등)이 막힘 | 라이브러리 파일을 `.shots/` 등 저장소 안(커밋 안 되는 곳)에 받아 두고 `"route": {"**/파일이름.js": ".shots/파일이름.js"}` |
| 공유 창(`navigator.share`)·파일 저장 창 | 점검 브라우저에는 없어서 앱이 내려받기로 넘어감 → `download` 단계로 받음 |
| 시간이 오래 걸리는 내보내기 | `"timeout": 180000` (ms) 을 그 단계에 |

## 예전 형식 자료로 시험하기
저장 형식을 바꿨다면(`data-migration` 스킬) 시나리오 `seed` 에 **새 형식 1건 + 예전 형식 1건 + 빈 칸(null)이 있는 1건**을 함께 넣는다. 예전 자료가 '모름'으로 나오고 오류가 없어야 통과.

## 개인정보 규칙 (CRITICAL)
- 시나리오 자료는 **가짜만**: 이름 `홍길동`, 연락처 `010-0000-0000`. 실제처럼 보이는 전화번호나 `.claude/pii-names.local.txt` 의 이름이 있으면 스크립트가 **실행하지 않고** 5번으로 끝낸다 — 자료를 고친 뒤 다시.
- 실제 회원이 있는 기기 저장소·계정으로 하지 않는다 (점검 브라우저는 매번 빈 저장소에서 시작한다).
- 사진 자료가 필요하면 캔버스로 만든 단색 그림을 쓴다. 실제 사람 사진을 시나리오에 넣지 않는다.
- `.shots/` 결과물은 커밋하지 않는다.
