# 손님 링크 (로그인 없는 화면)

> MEDICALLINK(환자 대기·입원 화면)와 바디샷(회원 공유 리포트)에서 쓴 방법이다(2026-10 기준). 개인정보가 바로 걸려 `plan-gate` 대상 — 계획서 승인 뒤 만든다. 바깥으로 나가는 그림·파일은 `export-privacy` 도 함께.

## 1. 원칙
- 손님 요청은 **표를 직접 못 읽는다**(anon 에게 표 권한 0). 읽고 쓰는 길은 `security definer` 함수뿐이고, 함수는 열쇠로 **자기 한 줄**만 찾아 **정해진 열**만 돌려준다(이름은 가린 이름 `홍*동`, 연락처는 안 줌).
- **익명 로그인 + RLS 는 쓰지 않는다.** 익명 사용자도 `authenticated` 라서 정책 하나에서 직원 조건만 빠져도 샌다. 익명 계정 청소·봇 방지도 따로 필요.

## 2. 열쇠 (손님 한 명·한 건용)
- 무작위 24바이트(hex 48자)를 **서버 함수**(`gen_random_bytes(24)`)가 만들고 원문은 발급 응답으로 한 번만 돌려준다(브라우저에서 만든다면 `crypto.getRandomValues`, `Math.random` 금지). 추측이 불가능해 시도 횟수 제한이 필요 없다.
- **DB 에는 sha256 해시만** 저장. 원문은 주소의 `#k=` 뒤와 손님 기기 localStorage 에만.
  - `#` 뒤는 브라우저가 서버로 보내지 않아 **접속 기록에 남지 않는다.** `?k=` 는 쓰지 않는다.
  - 열쇠를 기기 저장소에 넣은 **직후 주소창의 `#` 뒤를 지운다**: `history.replaceState(null, '', location.pathname + location.search)` — 안 지우면 방문 기록·화면 공유·캡처에 남는다.
  - 그 페이지의 다른 회사 스크립트는 `#` 뒤를 읽을 수 있다 → 손님 화면에는 외부 분석 스크립트를 넣지 않는다.
- 새 열쇠를 만들면 옛 링크·QR 은 즉시 무효. 여러 기기(보호자 폰)가 같은 QR 을 써도 된다 — 그래서 1회용으로 만들지 않는다.
- **만료**: 당일 쓰는 것은 그날만, 오래 쓰는 것은 "끝나는 일(퇴원 등)" 또는 발급 N일 중 먼저. 열쇠를 확인하는 **함수 한 곳**에서 만료를 검사하면 그 함수를 쓰는 모든 함수에 한 번에 걸린다.
- 만료된 열쇠와 없는 열쇠를 **구별하지 않는다** — "사용할 수 없는 링크예요. 새 링크를 요청해 주세요" 하나. 구별하면 "한때 진짜였다" 는 정보가 샌다.

## 3. 공개 화면용 기관 토큰 (대기실 TV·접수 QR)
- 기관마다 `public_token`(16바이트 무작위)을 두고 주소 `#o=` 뒤에. 함수가 토큰으로 기관을 찾는다.
- 이 토큰은 **원문 저장**해도 된다(예외) — QR 을 다시 인쇄할 때마다 원문이 필요하고, 얻는 것은 공개 화면에 이미 나가는 정보뿐.
- 추측 가능한 짧은 코드(`?org=center-a`)는 쓰지 않는다 → 남의 기관에 거짓 신청이 가능해진다.
- 공개용 **뷰(view)는 쓰지 않는다.** 뷰는 인자를 못 받아 기관을 가를 수 없고, 화면이 거르는 방식은 그 필터를 빠뜨린 버그 하나가 곧 전 기관 노출이다.
- 기관이 정해지는 출처는 언제나 **행의 `organization_id`**. 토큰은 짝이 맞는지 검사용 (`multi-org`).

## 4. 함수 권한 — 가장 많이 빠뜨리는 것
Supabase 는 public 스키마 함수에 **기본으로 anon 실행 권한**을 준다. 새 함수마다:
```sql
revoke execute on function my_entry(text) from public, anon, authenticated;
grant execute on function my_entry(text) to anon, authenticated;   -- 손님 함수만 (직원이 로그인한 브라우저에서도 열리게 — 보안은 열쇠 검사가 지킨다)
```
- 함수 안에 `set search_path = public` 을 둔다.
- Supabase 보안 점검이 손님 함수에 `anon_security_definer_function_executable` 경고를 띄운다 — **의도한 것**이다. 경고를 없애려고 권한을 빼거나 `security invoker` 로 바꾸면 손님 화면이 멈춘다. 대신 새 함수가 이 목록에 생기면 "열쇠로 자기 한 줄만 다루는지" 확인한다. 앱 `docs/ADR.md` 에 이 함수 목록을 적어 둔다.
- 손님이 무언가를 **넣는** 함수(셀프 접수·요청)에는 하루 상한과 잠금(기관별)을 둔다.

## 5. 화면
- 손님 화면은 보이는 동안 몇 초마다 다시 읽는다(실시간 구독은 손님에게 열지 않음). 늦는 만큼은 알림으로 보완(`web-push`).
- 오류·만료 문구는 손님이 할 일 하나로 (`ux-writing`).
- 손님 화면에도 `made by AYOCODING`.

## 6. 공유 리포트 링크 (바디샷 방식)
회원에게 결과를 보내는 링크.
- 결과 그림은 **비공개 버킷**에 두고, 링크는 서버 함수를 거쳐 **10분짜리 서명 주소**로만 보여 준다(공개 주소를 DB 에 두지 않음).
- 링크 기간은 마지막 갱신 뒤 최대 N일(바디샷 100일), **만료 시각은 서버 함수가 서버 시각으로** 정한다(앱이 정하지 않음).
- [중지] 는 즉시 차단, [새 링크 만들기] 로 이미 퍼진 링크를 끊는다.
- 회원당 **대표 링크 하나**를 갱신한다(링크가 계속 늘지 않게, 옛 링크도 최신을 보여 줌).
- 서버 저장이 필요 없는 작은 정보(다음 측정 안내 날짜 등)는 주소 `#` 뒤에 싣는다.
- 공유 동의가 없는 항목(얼굴 등)은 기기 안에서 가린 뒤 올린다. 동의가 없는데 **얼굴을 찾지 못한 사진은 가리지 못한 것이니 빼고** 올린다 (`export-privacy`).
- 계정 삭제 때 공유 그림도 함께 지운다 (`login-account` 4번).

## 7. 점검
- [ ] anon 으로 표를 직접 select 하면 0건
- [ ] 틀린 열쇠·만료 열쇠·다른 기관 토큰으로 함수를 부르면 0건(같은 문구)
- [ ] 돌려주는 열에 연락처·생년·전체 이름이 없다
- [ ] 새 함수 모두 권한 회수 후 grant
- [ ] 주소에 열쇠가 `#` 뒤에만 있고, `console.log`·오류 메시지에 열쇠를 남기지 않는다
